# ADR-025 — Executable v1 contract freeze

- Status: Accepted, 2026-11-21
- Authority: Requested contract milestone and authorization to resolve blocking choices
- Owners: Member_1 topology/Registry; Member_2 events/windows; Member_3 control; Member_4 API/SSE/agent/identity
- Implements: ADR-007, ADR-008, ADR-009, ADR-014, ADR-016, ADR-021 and ADR-023 at the contract boundary. Runtime acceptance remains separate.

## Context and decision

Freeze the approved prose as [schemas/v1](../../schemas/README.md). JSON Schema Draft 2020-12 defines events and shared REST/agent shapes in `bundle.json`; OpenAPI 3.1.1 defines routing and references that bundle. Protobuf defines Registry messages/RPCs. `make bindings` generates Python bindings/descriptors into ignored `.tools/generated` and derives the bundle's Device/DeviceType definitions from Protobuf. Normal checks reject stale generated definitions. Do not hand-maintain a second capability definition.

Use the already selected jsonschema 4.23.0 and pytest 8.3.5. Add grpcio-tools 1.71.0 (bundled protoc, no host JDK/compiler) and openapi-spec-validator 0.7.2 in an independent contract venv. Its [hashed lock](../../requirements-contracts.txt) pins all 27 distributions and published wheel hashes; Mac ARM64 and Linux x86_64 CPython 3.12 wheels were downloaded with hash verification. grpcio 1.85.3 and protobuf 5.29.6 satisfy the compiler metadata; this environment is separate from future PyFlink/Beam dependencies. See [upstream Protobuf language rules](https://protobuf.dev/programming-guides/proto3/), [compiler package](https://pypi.org/project/grpcio-tools/1.71.0/), [JSON Schema specification](https://json-schema.org/draft/2020-12), and [OpenAPI 3.1.1](https://spec.openapis.org/oas/v3.1.1.html).

Compatibility is deliberately conservative: preserve existing definitions, types, enums, constants, required fields, units, partition keys, RPC descriptors, routes, authorization, and response shapes. Optional properties may be added to ordinary JSON objects; tool argument/context changes require review. Other changes fail closed, including some changes that might be wire compatible. A new major contract and reviewed migration are the escape hatch. Comments/descriptions can change. Semantic/access review is still required; no syntactic checker can establish unchanged meaning. CI compares the actual Git base and runs deliberate breaking mutations. The initial introduction has no preceding executable v1 to compare; it still runs every example, schema and mutation check. Baseline schemas are read from Git, not hand-maintained copies.

## Resolved v1 details

- Kafka event types and keys are enumerated in the bundle's `x-events` and each event's `x-partition-key`. Action and charger-command are the fenced control envelopes and require `leader_epoch`/`saga_version`; command results report effects and do not claim leadership. Header `traceparent` is propagated separately. DLQ preserves the original key (nullable when unavailable); a malformed raw payload can be retained as a JSON string in `original_event` with a safe validation reason.
- IDs are nonblank, case-sensitive, at most 128 ASCII letters/digits/period/underscore/colon/hyphen. Event IDs are UUIDs. Preserve event/command/operation/request IDs across retries. Correlation and causation IDs are opaque stable IDs, not necessarily UUIDs. Power is finite kW; telemetry generation is negative, but `solar_generation_kw` is its nonnegative magnitude, so net = meter + EV − solar.
- Window start/end are whole UTC seconds on five-second boundaries. `window_id = UUIDv5(NAMESPACE_URL, "smart-grid/v1/window/{transformer_id}/{window_start}/5")`; `load.event_id = UUIDv5(NAMESPACE_URL, "smart-grid/v1/load/{window_id}/{revision}")`. Use canonical `YYYY-MM-DDTHH:MM:SSZ` for the window start. Other timestamps permit RFC3339 fractional seconds but require UTC `Z`. Compare instants, never timestamp strings. Numeric comparisons allow absolute tolerance 1e-9; golden utilization is rounded to nine decimals.
- Deduplicate telemetry before aggregation. Latest sample ordering is `(event_time, sequence_number)`; producers must not issue different readings at the same tuple for one device. A new boot gets a new boot ID. Watermark is greatest accepted event time minus ten seconds. The five-second windows, inclusive end+30-second correction limit, and strict age>15-second stale rule remain unchanged. If less than 70% is represented, STALE takes precedence even when a selected sample is estimated; otherwise any estimate makes PARTIAL. COMPLETE requires ≥95% GOOD with no estimates and valid capacity. Missing is never zero-filled. `late_event_count` counts unique accepted arrivals after window_end, including superseded samples, and excludes duplicates/DLQ/very-late audit.
- Registry uses **paginated unary** ListEligibleChargers, not an open-ended stream: limit 1–200 (client default 50), opaque cursor, evaluation time and policy version. Capabilities must be verified and at most 15 seconds old at plan evaluation. IDs/types/version/update timestamp are mandatory; rates are finite, 0 ≤ minimum ≤ maximum, priority 0–100; only EVs can be controllable. Departure absence means no constraint. Registration is idempotent by operation ID and capability version: equal version/equal payload returns current state; equal version/different payload → ALREADY_EXISTS; lower version → FAILED_PRECONDITION. Heartbeats cannot silently change capability/assignment; missing device → NOT_FOUND, version mismatch → FAILED_PRECONDITION. Invalid input → INVALID_ARGUMENT. Dependency outage → UNAVAILABLE. Exhausted client deadline → DEADLINE_EXCEEDED. Registry calls have a 2s end-to-end default deadline; retry transient failures at most twice within it using the same operation ID. Service identity/trace/deadline travel in gRPC metadata.
- Accept default policy: warning 80%, critical 95%, recovery 75%; cooldown 30s; two consecutive fresh COMPLETE windows at/below recovery before restore; command TTL 10s; acknowledgement timeout 5s. Thresholds require recovery < warning < critical; ack timeout ≤ TTL. Enter WARNING at ≥80% and CRITICAL at ≥95%. The reduction target is max(0, net load − capacity × recovery_pct/100). Reduce priority 0 first (least important), then latest departure (absent departure sorts last in urgency), then lexical device ID; each reduction is bounded by current minus minimum rate. Exclude offline/noncontrollable chargers and departures within five minutes. Cooldown starts at the preceding plan creation and never permits concurrent active sagas. These adopt the design’s proposed 75%/two-window recovery defaults; they are scenario defaults, not measured utility settings. Policy version increments exactly once using expected_version. Missing/stale state cannot imply recovery; partial/time-out outcomes require reconciliation/operator review. Preserve the documented saga transitions and all earlier audit history after corrections.
- Commands expire at `now >= expires_at`. Devices reject lower epochs before applying an unseen command and persist the greatest accepted epoch with the effect/dedup result. A previously applied command returns ALREADY_APPLIED without repeating its effect, including after expiry or leadership changes. Reusing a command ID for a different logical command is invalid producer behavior. One logical command per action/device/type; target rate must satisfy authoritative device capabilities. Restore is an explicit command, never deletion of history.
- REST lists default to 50, cap 200; cursors are opaque. All mutations require Idempotency-Key. Internal calls have 3s deadlines, authenticated service identity, trusted actor/role, request ID, trace context and bounded payloads. The API maps validation→400/422, missing auth→401, insufficient role→403, absent entity→404, optimistic/idempotency conflict→409, limits→429, dependency outage→503, deadline→504. Error details are bounded field/reason pairs; never backend queries, secrets or stack traces.
- SSE uses `id: cursor`, `event: event_type`, and one JSON `SseEvent` in `data`, separated by a blank line. Heartbeat comments every 15s. Retain up to 1000 events or five minutes, whichever is shorter. Cursor gaps emit `snapshot.required` then clients reload REST; investigation reconnect first fetches its REST status. Payloads carry authoritative versions/freshness; model progress contains tool names/status only.
- Local OIDC baseline: realm `smart-grid`, public client `smart-grid-ui`, authorization code + PKCE S256, no browser client secret; roles Viewer < Operator < Administrator. Administrator inherits Operator/Viewer permissions; Operator inherits Viewer. The API validates issuer/audience/signature/expiry and enforces the OpenAPI minimum role. Internal trusted headers require service authentication and cannot be accepted directly from the browser. Actual realm/bootstrap/redirect URIs and token tests belong to the identity component milestone; these names/roles are fixed here.
- Agent context is server-owned and separate from model tool calls. Only the seven existing tools are accepted, with approved entity/time scope; trace/correlation IDs must already be evidence-authorized. Tool limit is clamped to the server cap, at most 200; time range must be positive and ≤1h. Investigation defaults: 30s deadline, ≤12 tool calls, ≤6 model turns, ≤64KiB per tool response, ≤2 concurrent investigations per actor, ≤6 starts/minute per actor. One schema repair attempt stays inside those budgets. A timeout yields PARTIAL or FAILED with explicit unknowns. Every factual observation needs evidence returned within that investigation. Hypotheses are separately typed. Relative application deep links must also pass caller authorization. The offline validator checks shape, scope and evidence IDs; it cannot prove a natural-language claim true or authorize an application route without the future service. Provider mode is MOCK for v1; external calls and write tools remain deferred.

## Alternatives and consequences

A runtime schema registry, authored DTO mirrors, a new agent framework, and application service scaffolds would add operational or maintenance work without helping this gate. Use standard offline libraries and shared fixtures instead. The reference replay is a small executable specification with fixed expected outputs, not a PyFlink implementation, Kafka integration, persisted device effect, authentication server, or recovery proof. Each future component must run these fixtures against real behavior and add its own success/failure tests. Cloud remains deferred. ARM64 PyFlink build/import/checkpoint proof remains the next packaging risk, not an unresolved language choice.
